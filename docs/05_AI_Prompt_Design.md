# zhdate AI Calendar Prompt 设计文档（AI Prompt Design）


# 1. Prompt设计目标


zhdate 的核心能力是：

> 将用户自然语言转换为结构化日程数据。


例如：

用户输入：

```
周三下午五点给朋友过生日
```


AI需要理解：

- 做什么事情？
- 什么时间？
- 是否需要提醒？


最终生成：

```json
{
"title":"朋友生日",
"date":"周三",
"time":"17:00",
"advice":"提前准备礼物"
}
```


---

# 2. AI任务定义


## AI角色（Role）


将模型定义为：

```
你是一名智能日程助手。
你的任务是帮助用户创建和管理日程。
```


目的：

让模型明确自己的身份和任务范围。


---

# 3. System Prompt设计


核心 Prompt：


```
你是一个智能日程管理助手。

请分析用户输入的信息，
提取其中的事件名称、日期、时间。

你必须返回JSON格式。

字段包括：

title:
事件名称

date:
日期

time:
时间

advice:
提醒建议

不要输出额外文字。
```


---

# 4. 输出格式设计


## 为什么使用JSON？


如果AI返回普通文本：

例如：

```
你周三下午五点参加朋友生日。
```


程序无法稳定获取：

- 标题
- 日期
- 时间


因此设计固定结构：


```json
{
"title":"",
"date":"",
"time":"",
"advice":""
}
```


---

通过提供示例，提高模型理解能力。


## Example 1


# 6. Prompt优化过程


## 初始版本问题


早期直接要求模型：

"帮我创建一个日程"


可能出现：

- 输出格式不固定
- 缺少时间字段
- 返回解释文字


---

## 优化方案


### 优化1：限制输出格式


增加：

```
只返回JSON
```


效果：

提高程序解析稳定性。


---

### 优化2：明确字段


增加：

```
title
date
time
advice
```


效果：

统一前后端数据结构。


---

### 优化3：加入任务示例


增加Few-shot：

效果：

提升模型对于中文时间表达的理解。


---

# 7. 中文时间理解挑战


用户表达时间具有多样性。


例如：


```
明天上午
```


```
下周五下午
```


```
月底
```


```
过两小时
```


这些表达需要模型进行语义理解。

# 8. AI效果评估指标


为了评估AI解析能力，可以设计：


## 1. 信息提取准确率


测试：

用户输入100条日程。

统计：

正确提取数量。


公式：

```
准确率 =
正确解析数量 / 总测试数量
```


---

## 2. JSON格式成功率


衡量：

AI输出是否符合要求。


---

## 3. 用户体验指标


关注：

- 创建时间减少
- 输入步骤减少
- 用户满意度
