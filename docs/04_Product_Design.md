# zhdate AI Calendar 产品设计文档（Product Design）


# 1. 产品设计理念


## 1.1 设计目标


传统日历产品的核心流程：

```
打开日历

↓

选择日期

↓

填写事件

↓

设置提醒

↓

保存
```


zhdate 希望降低用户操作成本。


新的交互方式：

```
用户表达需求

↓

AI理解意图

↓

自动生成日程

↓

用户确认
```


核心理念：

> 让用户像聊天一样管理时间。


---

# 2. 用户使用流程（User Flow）


## 场景示例


用户输入：

> 周三下午五点给朋友过生日


系统处理流程：


```
用户输入自然语言

        ↓

AI语义理解

        ↓

提取关键信息

        ↓

生成结构化数据

        ↓

展示日历事件

        ↓

生成提醒建议
```

# 3. AI交互设计


## 3.1 输入设计


用户无需学习固定格式。


支持自然语言：

例如：


```
明天下午三点提交实验报告
```


```
周末晚上和朋友吃饭
```


```
下个月参加机器学习比赛
```


AI负责理解用户意图。


---

# 3.2 信息抽取设计


用户输入：

```
周五下午5点参加朋友生日聚会
```


AI提取：

```json
{
"title":"朋友生日聚会",
"date":"周五",
"time":"17:00",
"advice":"提前准备礼物"
}
```


其中：


|字段|作用|
|-|-|
|title|事件名称|
|date|日期|
|time|时间|
|advice|AI建议|


---

# 4. 为什么采用JSON结构化输出


## 问题


如果 AI 直接返回普通文字：

例如：

> 你周五下午五点参加生日聚会。


前端无法准确识别：

- 日期
- 时间
- 标题


---

## 解决方案


要求 AI 返回固定 JSON：


```json
{
"title":"",
"date":"",
"time":"",
"advice":""
}
```


优势：


### 1. 前后端容易通信


后端可以直接解析。


### 2. 数据格式统一


方便未来扩展：

- 数据库存储
- 日历同步
- 用户画像


### 3. 提升系统稳定性


减少模型输出格式错误。

# 5. 页面交互设计


## 首页设计


主要区域：


### AI输入区域


作用：

用户输入自然语言计划。


设计原则：

- 降低输入门槛
- 突出AI入口


---

### 日历区域


作用：

展示用户已经创建的事件。


帮助用户：

- 查看安排
- 管理时间


---

### AI反馈区域


展示：

- 创建结果
- 提醒建议


增强用户信任。


---

# 6. AI Prompt设计思路


为了提高模型稳定性，对AI任务进行限制。


Prompt要求：


1. 明确角色

```
你是一个智能日程助手
```


2. 明确任务

```
提取用户输入中的时间和事件
```


3. 明确输出格式

```
只返回JSON
```

## 当前版本

✅ 日历展示

## 后续优化


### 日程确认机制


AI生成后：

询问用户：

> 是否添加到日历？


避免错误创建。


---

### 多轮对话


例如：

用户：

> 明天下午开会


AI：

> 请问几点？


用户：

> 三点


AI：

自动补充完整信息。


---

### 智能调整


当发生冲突：

AI提示：

> 当前时间已有安排，是否调整？

# 8. 产品设计总结


zhdate 的核心设计不是简单增加 AI 功能。


而是重新设计：

用户 → 日历

之间的交互方式。


从：

> 用户适应工具


转变为：

> 工具理解用户
